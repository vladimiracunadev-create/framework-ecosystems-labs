# Versiones y actualización

## Política

El currículo enseña conceptos estables. El catálogo registra fecha de verificación. Los laboratorios fijan versiones solo cuando son necesarias para reproducibilidad y deben explicar cómo actualizarlas.

## Revisión de una actualización

1. Lee guía oficial de versión y migración.
2. Identifica breaking changes, soporte de runtime y dependencias.
3. Ejecuta pruebas de contrato y seguridad.
4. Compara construcción, tamaño y rendimiento con el mismo protocolo.
5. Revisa plugins y adaptadores.
6. Documenta rollback y cambios de datos.
7. Actualiza catálogo, fuentes y changelog.

## Estado de tecnologías

No uses “vigente”, “recomendado”, “LTS” o “abandonado” sin fecha y fuente oficial. Si el gobierno es ambiguo, decláralo como riesgo en vez de adivinar.
