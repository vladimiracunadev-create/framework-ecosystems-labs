# 🔨 Mithril — 2014

> [⬅️ Atlas](../README.md) · [🟨 Ecosistema JavaScript](../ecosistemas/javascript.md) · [🗂️ Índice](../frameworks.md)

Mithril incluye componentes, enrutado y peticiones **en unos pocos kilobytes**.
Es el recordatorio de que un framework completo no tiene por qué ser grande.

## 💡 Completo y pequeño no son opuestos

Mithril trae las tres piezas que una aplicación de página única necesita
—vista, enrutado y peticiones— con una superficie de API muy reducida.

Eso contrasta con la observación de la [ficha de React](react.md): React es más
pequeño y **no trae** enrutado ni datos, así que un proyecto real acaba con más
kilobytes y con ocho decisiones más. Mithril invierte el reparto.

Para el [módulo 11](../../curriculum/11-seleccion-y-sostenibilidad.md), la lección
es sobre **qué se compara**: el tamaño de una biblioteca aislada dice poco; lo que
importa es el tamaño del conjunto que hace falta para el producto.

## ⚖️ Su límite

Ecosistema pequeño, poca gente disponible y menos ejemplos. Y su superficie
reducida se paga cuando el producto necesita algo que no está incluido.

Es el mismo balance de todas las bibliotecas fuera de la corriente principal
—[Knockout](knockout.md), [Aurelia](aurelia.md), [Marko](marko.md)—: buen diseño,
poca red de apoyo.

## 🎓 Las dos lecciones

**1. Compara conjuntos, no piezas.** «Biblioteca X pesa menos que framework Y»
no dice nada si X necesita cinco piezas más para hacer lo mismo.

**2. Un framework completo puede ser diminuto.** Tamaño y alcance son dimensiones
independientes.
